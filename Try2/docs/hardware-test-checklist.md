# 原代 EOS R6 真机测试清单

这份清单用于第一次把 R6 Monitor 接到目标硬件。一次只验证一个阶段；失败后停止、导出日志，不要连续盲试。

## 准备

- [ ] 确认相机是原代 **EOS R6**，不是 R6 Mark II 或 Mark III。
- [ ] 记录 R6 固件版本、iPhone 型号和 iOS 版本。
- [ ] 准备一根已验证能传文件的 USB-C to USB-C 数据线。
- [ ] R6 电量充足，切到拍照模式，退出菜单。
- [ ] 结束 R6 的 Wi-Fi、蓝牙遥控和 EOS Utility 连接。
- [ ] 在 Xcode 中使用测试者自己的 Personal Team 安装最新代码。

## Gate 1：设备发现

1. 先打开 App，再连接并开启 R6。
2. 处理 iOS 弹出的外接相机控制授权。
3. 等待 10 秒。

通过标准：界面显示正在连接 Canon EOS R6；诊断日志出现 `Camera added`，vendor 应为 `0x04A9`。

失败处理：更换已知可传数据的线，交换插头方向，重新启动相机和 App 后只重试一次。仍失败则导出日志，并说明 iOS 是否出现授权提示。

## Gate 2：ImageCapture 会话

通过标准：日志出现 `ImageCapture session opened`。

失败处理：确认没有其他 App 或电脑占用相机。导出日志，不继续后续命令。

## Gate 3：远程模式与事件模式

通过标准：日志中以下操作均返回 `response=0x2001`，并保持此顺序：

1. `op=0x9114`
2. `op=0x9115`

失败处理：立即停止。记录失败操作码和响应码，导出日志。不要重复十几次尝试。

## Gate 4：开启 EVF

通过标准：两个 `op=0x9110` 都返回 `0x2001`。相机屏幕或状态可能短暂变化，但相机不应死机或失去菜单响应。

失败处理：点“停止”或拔线，确认相机恢复正常，然后导出日志。记录失败发生在第一个还是第二个 `0x9110`。

## Gate 5：首帧

通过标准：日志出现 `op=0x9153 response=0x2001 bytes=` 且字节数大于零，iPhone 显示一帧相机画面。

失败处理：导出日志，并说明是相机拒绝命令、返回零字节，还是 App 报告连续五帧无法解析。不要发送照片或画面；诊断文本足够定位协议层。

## Gate 6：连续监看

- [ ] 连续显示 10 分钟。
- [ ] 横竖屏各切换一次。
- [ ] 观察帧率是否稳定，记录大致范围。
- [ ] 记录相机和 iPhone 是否明显发热。
- [ ] 确认 App 没有保存照片或视频。

## Gate 7：清理与恢复

- [ ] 点“停止”，确认日志最后出现两个 `0x9110` 清理命令和 session closed。
- [ ] 重新拔插线，确认可以建立新会话。
- [ ] 串流时锁屏或切到后台，再回到 App，确认会话会安全停止并重新建立。
- [ ] 串流时关闭相机，确认 App 不崩溃且回到连接提示。

## 回传内容

请发送：

- R6 固件版本；
- iPhone 型号和 iOS 版本；
- 数据线品牌或标称速率（如果知道）；
- 最后通过的 Gate 编号；
- App“诊断”按钮导出的完整文本；
- 看到的界面错误文字。

不要发送 Apple ID、开发证书、描述文件、设备序列号或相机拍摄内容。
