# Codex Remote 截图脚本

建议优先使用 `审核演示模式` 来拍第一版截图。这样不用依赖真实 Mac 环境，也能保证画面稳定、文案一致。

## 目标

准备一套中国区 iPhone 截图，突出：

1. 这是 `Codex 的移动控制台`
2. 首页先看总览和压力
3. 可以接管等待输入的会话
4. 可以查看命令回执和事件时间线

## 截图顺序建议

### 1. 首次打开 + 使用帮助

- 页面：帮助中心首页
- 重点：这是 Codex 的 iPhone 副控端
- 建议标题文案：
  - `把 Mac 上的 Codex 装进口袋`

### 2. 连接页 + 审核演示模式

- 页面：连接主控 Mac
- 重点：支持恢复设备、发现附近 Mac、快速接入、审核演示模式
- 建议标题文案：
  - `连接主控 Mac，也能先看演示`

### 3. 首页总览

- 页面：首页 Hero + 总览卡 + 焦点任务
- 重点：待接管、运行中、异常、自动化
- 建议标题文案：
  - `先看总览，再决定先处理什么`

### 4. 待处理队列

- 页面：首页待处理队列
- 重点：等待输入 / 异常 / 执行中的状态区分
- 建议标题文案：
  - `焦点任务和待处理队列一眼可见`

### 5. 会话详情

- 页面：会话详情顶部 + 操作状态 + 动作区
- 重点：继续输入、继续运行、重试、停止
- 建议标题文案：
  - `进入会话，继续推进任务`

### 6. 命令回执 + 事件时间线

- 页面：最近命令 + 事件时间线
- 重点：看回执、看轨迹、判断下一步
- 建议标题文案：
  - `回执和轨迹，帮助你快速判断`

## 截图拍摄建议

- 使用统一设备尺寸
  - 第一版建议先用 `iPhone 6.9"` 或 `6.7"` 规格
- 使用同一套演示数据
  - 保证每张图之间的任务名称、状态、数字不冲突
- 顶部状态保持干净
  - 避免杂乱通知、异常网络图标、调试条
- 文案不要过长
  - 一张图只讲一个重点
